# MdForConventer

Спецификация Markdown-формата для Conventer.

Описывает, какие конструкции поддерживаются и как они превращаются
в `.docx` по СТП 01-2024 (БГУИР).

Документ рассчитан на две аудитории:

- **авторы** — как писать `.md`, чтобы получить правильный `.docx`;
- **LLM/AI** — как генерировать `.md`, который без ручной правки
  пройдёт через конвертер.

---

## 1. Структура документа

### 1.1. Разделы (H1)

```markdown
# Анализ системы управления
```

Превращается в `1 АНАЛИЗ СИСТЕМЫ УПРАВЛЕНИЯ` — номер присваивается
автоматически, ПРОПИСНЫМИ, с новой страницы.

**Не пишите номер вручную.** Правильно: `# Анализ`.
Неправильно: `# 1 Анализ`.

### 1.2. Специальные разделы

Эти H1 не нумеруются, оформляются по центру, с новой страницы:

- `# Введение`
- `# Заключение`
- `# Содержание`
- `# Реферат`
- `# Список использованных источников`
- `# Перечень условных обозначений`
- `# Перечень условных обозначений, символов и терминов`

Регистр в исходнике не важен — конвертер сам сделает ПРОПИСНЫМИ.

### 1.3. Подразделы (H2)

```markdown
## Общие сведения
```

Превращается в `1.1 Общие сведения`.

### 1.4. Подподразделы (H3)

```markdown
### Детали
```

Превращается в `1.1.1 Детали`. Уровни H4+ не поддерживаются —
используйте перечисления.

### 1.5. Приложения

```markdown
# Приложение А
## Схема электрическая принципиальная
```

Превращается в:

- `ПРИЛОЖЕНИЕ А` (без номера, по центру, с новой страницы);
- `А.1 Схема электрическая принципиальная`.

Буквы приложений присваиваются автоматически (А, Б, В, …).

---

## 2. Текст

Обычные абзацы. Пустая строка между абзацами — обязательна.

```markdown
Первый абзац.

Второй абзац.
```

Первая строка — отступ 1.25 см, выравнивание по ширине,
Times New Roman 14 pt, межстрочный 18 pt.

Курсив `*текст*` и жирный `**текст**` сохраняются.

---

## 3. Формулы

### 3.1. Display-формулы

Отдельным абзацем:

```markdown
$$J\frac{d\omega}{dt} = M - M_c$$
```

Превращается в формулу с номером справа: `(1.1)`.

Номер присваивается автоматически:

- обычный раздел: `(N.M)` — N номер раздела, M счётчик формул
  внутри раздела;
- приложение: `(А.1)`, `(Б.1)`, …;
- спецразделы (Введение, Заключение): формулы не нумеруются.

**Не пишите номер вручную.** Неправильно: `$$...\qquad(1.1)$$`.

### 3.2. Inline-формулы

```markdown
где $J$ — момент инерции, $\omega$ — угловая скорость.
```

### 3.3. Поддерживаемая нотация

Всё, что понимает pandoc в режиме `tex_math_dollars`. Стандартный
LaTeX: `\frac`, `\sum`, `\int`, `\omega`, `\cdot`, `\qquad`, …

---

## 4. Рисунки

```markdown
![Структурная схема системы](img/scheme.png)
```

Превращается в:

- рисунок (отдельным абзацем, по центру);
- подпись под ним: `Рисунок 1.1 – Структурная схема системы`.

Номер присваивается автоматически:

- обычный раздел: `Рисунок N.M`;
- приложение: `Рисунок А.1`.

**Подпись — это alt-текст.** Именно он становится текстом подписи.
Не оставляйте его пустым.

Путь к файлу — относительный от `.md`. Pandoc должен найти файл
в момент конвертации.

---

## 5. Таблицы

```markdown
| Параметр | Значение |
|----------|----------|
| Частота | 50 Гц |
| Напряжение | 220 В |
: Параметры сети
```

- Первая строка — заголовки столбцов.
- Вторая — разделитель `|---|---|`.
- Далее — строки.
- **Строка, начинающаяся с `:`, — подпись таблицы.**

Превращается в:

- подпись сверху: `Таблица 1.1 – Параметры сети`;
- таблицу с границами, autofit по ширине страницы.

Номер присваивается автоматически.

---

## 6. Перечисления

### 6.1. Простое перечисление

```markdown
- датчик расстояния;
- фотодиодная матрица;
- задающий генератор.
```

Превращается в тире:

```
– датчик расстояния;
– фотодиодная матрица;
– задающий генератор.
```

### 6.2. Нумерованное перечисление

```markdown
1. Вычисляем передаточную функцию.
2. Определяем показатели качества.
3. Выбираем параметры коррекции.
```

Превращается в номера без точки:

```
1 Вычисляем передаточную функцию.
2 Определяем показатели качества.
3 Выбираем параметры коррекции.
```

### 6.3. Список литературы

В разделе `# Список использованных источников` нумерация сохраняется
с точкой (библиография по ГОСТ 7.1):

```markdown
1. Гук, М. Процессоры Pentium II... – СПб. : Питер, 1999. – 288 с.
2. Кузелин, М. О. Современные семейства ПЛИС...
```

Не путайте с обычным нумерованным перечислением.

---

## 7. Блоки кода

Блок с указанием языка:

```python
def compute_omega(J, M, Mc, dt):
    return (M - Mc) / J * dt
```

Оформляются стилем `SourceCode`: Courier New 12 pt, без отступа,
подсветка синтаксиса — tango.

Для СТП блоки кода не стандартизованы, но допустимы (листинги).

---

## 8. Сноски

```markdown
Текст с утверждением[^1].

[^1]: Под следящим приводом понимается замкнутая система
автоматического регулирования с отрицательной обратной связью.
```

Превращается в сноску внизу страницы. Знак — цифра со скобкой
(СТП 01-2024, п. 2.9.1).

**Важно:** определение сноски должно быть в том же файле.
Не оставляйте ссылки на сноски без определений.

---

## 9. Ссылки на источники

В тексте — обычные ссылки `[1]`, `[2]`. Это не markdown-ссылки,
а литеральные скобки.

Библиография — в разделе `# Список использованных источников`
нумерованным списком.

---

## 10. Оглавление

**Не пишите оглавление вручную.** Конвертер добавит `СОДЕРЖАНИЕ` —
поле TOC, которое заполнится при открытии документа в Word.

---

## 11. Чего не делать

- **Не нумеровать разделы и подразделы** — номер присваивается
  автоматически. `# 1 Анализ` превратится в `1 1 АНАЛИЗ`.
- **Не нумеровать формулы** — `$$...\qquad(1.1)$$` превратится
  в `... (1.1) (1.1)`.
- **Не писать подписи к рисункам отдельным абзацем** — они станут
  частью тела документа, а рисунок останется без подписи.
  Используйте alt-текст.
- **Не писать подписи к таблицам строкой после таблицы** — они
  не подхватятся. Используйте строку, начинающуюся с `:`.
- **Не оформлять спецзаголовки через `##` или `###`** — только `#`.
- **Не использовать `---`, `***` для разделителей** — они не нужны
  и попадут в документ как горизонтальные линии.
- **Не пропускать пустые строки** между абзацами — pandoc склеит
  их в один абзац.

## 13. Что получится в DOCX

На основе примера из раздела 12 в `.docx` появится:

**Страница 1** — поле TOC. При открытии в Word покажет вопрос
«Обновить поля?» — нажать «Да». Оглавление заполнится само.

**Страница 2** — `ВВЕДЕНИЕ`:
- H1 — по центру, ПРОПИСНЫМИ, стиль `SpecialHeading`, с новой страницы;
- обычный текст с отступом 1.25 см, по ширине;
- сноска `1)` внизу страницы.

**Страница 3** — `1 АНАЛИЗ СИСТЕМЫ УПРАВЛЕНИЯ`:
- H1 с номером, слева, ПРОПИСНЫМИ, с новой страницы;
- `1.1 Общие сведения` — H2;
- формула `(1.1)` — по центру, номер справа;
- `Рисунок 1.1 – Структурная схема системы` — подпись под рисунком,
  по центру;
- `Рисунок 1.2 – Функциональная схема`;
- `1.2 Расчёт параметров` — H2;
- `Таблица 1.1 – Параметры системы управления` — подпись над таблицей,
  слева;
- `Таблица 1.2 – Дополнительные величины`;
- формулы `(1.2)`, `(1.3)`, `(1.4)`;
- `1.3 Перечисления` — H2;
- перечисление через тире `– датчик расстояния;` и т. д.;
- нумерованное `1 Вычисляем …`, `2 По найденной …`, `3 Выбираем …`;
- `1.4 Выводы` — H2.

**Страница N** — `2 РАЗРАБОТКА АЛГОРИТМА`:
- H1 с номером 2;
- `2.1 Структура программы` — H2;
- блок кода стилем `SourceCode` (Courier New 12 pt);
- `2.2 Описание модуля` — H2.

**Страница N+1** — `ЗАКЛЮЧЕНИЕ` — как `ВВЕДЕНИЕ`, по центру,
ПРОПИСНЫМИ, с новой страницы.

**Страница N+2** — `СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`:
- H1 без номера;
- библиография с точками `1.`, `2.`, `3.` — как в исходнике.

**Страница N+3** — `ПРИЛОЖЕНИЕ А`:
- H1 без номера, по центру, с новой страницы;
- `А.1 Схема электрическая принципиальная` — H2 с буквенным номером;
- `Рисунок А.1 – Схема соединений` — подпись;
- формула `(А.1)`;
- `А.2 Перечень элементов`;
- `Таблица А.1 – Состав элементов`.

**Страница N+4** — `ПРИЛОЖЕНИЕ Б`:
- H1 без номера;
- `Б.1 Дополнительные расчёты`;
- формула `(Б.1)`;
- `Рисунок Б.1 – Осциллограмма`;
- `Таблица Б.1 – Параметры сети`.

Каждая страница получит номер в футере справа (Times New Roman 14 pt).
